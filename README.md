# pairwise media graphs

A Ghibli relationship-mapping prototype, using the original art axes pixel type, monospace controls, white panels, and pale canvas.

Run `npm install` once, then `npm run dev` and open http://localhost:8083.

Enter a name to open a browser-local participant session. The prototype presents all 45 unique pairs of ten films in round-robin order. Name a connection or skip; no explanation or strength rating is required. Make a map at any point, or after completing the pairs. Each participant’s progress, labels, and source weights persist separately in this browser. Previous v1 prototype data remains untouched.

The map combines three adjustable sources:

- **Personal label meaning:** each named pair gives both films its labels. Commas and semicolons split multiple labels; repeated labels count once per film. MiniLM embeds labels through the local server on localhost; a browser worker is used as a fallback and for static hosting. Each film is compared to every other film using symmetric best-match coverage: for each label, take its strongest cosine match in the other film’s label set, average within each film, then average the two directions. Thus films with semantically related labels can be close without a direct pairwise statement. Exact original statements and their provenance remain visible and editable. A film with no labels is missing evidence, not evidence of dissimilarity.
- **Factual metadata:** release years and directors are a local snapshot of the unofficial Studio Ghibli API, with per-film source URLs in `dist/films.js` and the inspector. This is not a live feed. Scores combine director match and year proximity equally, with linear decay over 30 years.
- **Synopsis meaning:** actual MiniLM text embeddings, computed locally from the ten original short summaries in `dist/films.js`. Similarity is cosine similarity of mean-pooled, L2-normalized embeddings, clamped to [0, 1]. These scores are bundled in `dist/synopsis-scores.js`. For personal labels, the same quantized model and its runtime are bundled under `dist/models` and `dist/vendor`. On localhost the page calls `POST /api/label-embeddings`, which runs the bundled model on this computer and caches vectors. If that endpoint is unavailable (including on static hosting), a browser worker loads about 45 MB from this site and runs inference locally. Vectors are cached in browser storage. No API key, remote model download, or third-party inference service is used. Names are not sent to the label endpoint.

The personal layout combines labels into shared theme magnets. Singular/plural variants collapse; automatic semantic merges use complete linkage with cosine similarity above 0.6, so weak similarity chains cannot absorb a distinct theme. The explicitly requested “whimsical worlds” / “fantastical” equivalence is recorded in `dist/theme-preferences.js`. A representative original label names each theme, whose embedding averages its members. Click a theme to inspect every original label and its source relationships, separate a grouping, or combine it with another theme. Participant-specific grouping choices persist. A magnet-count slider moves from one broad theme to all automatically identified themes. Reducing the count repeatedly merges the closest theme centroids, recomputes theme embeddings and semantic positions, and rearranges the films around the resulting magnets. Increasing the count restores more specific themes. Every original label remains inspectable; count selection persists. Theme magnets use distinct pastel colors and no star icon. Each film is pulled once per shared theme even if several of its original labels map to that theme. A sparse graph links each theme to its strongest related neighbors using cosine similarity boosted by shared-film associations. Local attraction, gentle repulsion, and text-overlap correction allow compact clusters and empty canvas areas; there is no fit-to-canvas spreading step. Existing dragged positions still override these proposals; each film is pulled toward the centroid of its own theme magnets. Metric MDS fits computational pair distances while explicit personal anchor penalties balance those pulls. Poster overlap is corrected separately from semantic coordinates; dots and dotted leaders identify any displaced posters. The personal pairwise score in the inspector is a summary, not the force driving this layout. Similarity does not infer an opposition relation. Drag magnets (or use arrow keys) to revise their positions; each participant’s adjustments persist, and reset restores the semantic arrangement. Original pairwise statements remain inspectable regardless of their influence. Lines are hidden until a poster is hovered or keyboard-focused; only that film’s incident connections are revealed. Touch or keyboard activation can pin the reveal; Escape clears it. Dashed lines show the two strongest neighbors for each film above 0.4; the selector provides access to every pair. Reveal and click a connection to inspect the exact inputs and scores, then revise its label. The map workspace fits the viewport and does not scroll with the page. The left sidebar scrolls independently. Click-and-drag empty canvas to pan; two-finger trackpad scrolling also pans. Pinch to zoom on touchscreens and trackpads (including Safari GestureEvents); zoom stays anchored under the gesture. The plus/minus buttons remain available and the percentage button fits the map into view. Pair contributions also fit the viewport without page scrolling.

To recalculate synopsis embeddings after editing film summaries, install the optional build dependency with `npm install --no-save @huggingface/transformers@3.8.1`, then run `node scripts/build-synopsis.mjs`. This downloads the public `Xenova/all-MiniLM-L6-v2` model. Names are never model inputs. Personal labels are model inputs on this computer through the local server or browser worker. Failed loading exposes its cause in a details panel and offers retry. Missing personal scores are excluded until ready; it never silently falls back to the previous link-only method. The worker coalesces rapid edits to avoid building up an obsolete inference queue.

Film posters are stored in `dist/posters`, with source URLs in `dist/films.js`, referenced through the [Studio Ghibli API](https://ghibliapi.vercel.app/) from [TMDB](https://www.themoviedb.org/). Poster artwork belongs to its respective rights holders; this prototype is not endorsed by TMDB or Studio Ghibli. Poster appearance is not compared by the map.

Research question: **How does negotiating between personal associations and computational descriptions help people articulate their interpretations of media?**

Run `npm test` for label aggregation and profile-comparison checks. Model assets include their license information.

The older artwork collection and fetch scripts remain in the repository but are not loaded by this prototype.

## Movie layout and reproducible comparison

`dist/movie-layout.js` implements deterministic metric MDS (SMACOF, 16 starts, lowest squared stress). Cosine scores become chord distances `sqrt(2*(1-score))`; enabled computational source distances are averaged by their relative weights. Personal targets add squared-distance anchor penalties; computational pair penalties are divided by `n-1` to balance the number of incident pairs against one personal target. Unlabeled movies receive no anchor penalty. With only personal influence, labeled movies reach their theme targets. All weights remain relative. With every source off, the layout is a neutral circle.

The semantic layout has no rectangular clamping. A uniform transform preserves aspect ratio; a separate poster collision pass changes only rendering. Fit view includes scene bounds rather than changing semantic coordinates. Theme placement retains its existing semantic clustering algorithm.

Run `node benchmarks/compare-layouts.cjs` and `node benchmarks/render-comparison.cjs` from the repo root. The old solver is preserved in `benchmarks/legacy-layout.cjs`, with its untouched original function alongside it. Results go to `reports/layout-comparison.json` and the locally served `/layout-comparison.html`. Comparison uses the same ten films and all 45 pair distances, three source settings, and three board sizes; it contains no participant labels. Normalized stress uses the best single scale fit, and Recall@2 counts true nearest neighbors retained out of 20 (metadata ties use stable index ordering). Semantic anchors and rendered poster centers are measured separately. The JSON additionally evaluates both layouts against the old target-distance transform. These are dataset-specific checks, not general validation of semantic judgments. `npm test` covers exact planar recovery, monotonic stress, determinism, personal constraints, relative weights, collisions, and existing app behavior.
