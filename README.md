# pairwise media graphs

A Ghibli relationship-mapping prototype, using the original art axes pixel type, monospace controls, white panels, and pale canvas.

Use Node 22+ for local inference and score builds. Run `npm install` once, then `npm run dev` and open http://localhost:8083.

Enter a name to open a browser-local participant session. Start by labeling suggested groups of the ten Ghibli films, or skip a group if nothing connects them. Groups use deterministic average-link clustering of the bundled MiniLM synopsis similarity scores, with a size limit so groups remain easy to compare. Switch between three broader groups and five smaller groups. Labels are supplied by participants, never generated by the clustering.

Each label becomes a personal magnet. After naming a group, rank only its films from least to most connected to that theme. Drag posters to reorder, or use the arrow buttons with mouse, touch or keyboard. Saving seeds increasing magnet strengths from 25 to 100 across the ranking (a singleton receives 70); these are relative starting strengths, not participant-supplied absolute ratings. Group membership and rank order are stored alongside the strengths. Films outside the ranked group retain their existing ratings; new magnets start those films at zero. Revisit a group to edit its theme and ranking. The map still allows per-film strength adjustments across the collection, plus adding, renaming and deleting magnets. Labels, rankings, ratings, group progress and map settings persist per participant in this browser. The group-based flow uses a fresh v3 participant store. On loading it, the old v2 participant sessions (including pairwise answers and the earlier mixed group maps) are cleared. Subsequent v3 group sessions persist normally. Pair comparisons remain inspectable, but direct pairwise labels are no longer loaded, entered or used as personal map evidence. The collection remains limited to the existing ten Ghibli films.

The map combines six adjustable sources. New title and poster influences start at zero so saved maps keep their existing balance until a participant turns them up:

- **Personal label meaning:** each named pair gives both films its labels. Commas and semicolons split multiple labels; repeated labels count once per film. MiniLM embeds labels through the local server on localhost; a browser worker is used as a fallback and for static hosting. Each film is compared to every other film using symmetric best-match coverage: for each label, take its strongest cosine match in the other film’s label set, average within each film, then average the two directions. Thus films with semantically related labels can be close without a direct pairwise statement. Exact original statements and their provenance remain visible and editable. A film with no labels is missing evidence, not evidence of dissimilarity.
- **Factual metadata:** release years and directors are a local snapshot of the unofficial Studio Ghibli API, with per-film source URLs in `dist/films.js` and the inspector. This is not a live feed. Scores combine director match and year proximity equally, with linear decay over 30 years.
- **Synopsis meaning:** actual MiniLM text embeddings, computed locally from the ten original short summaries in `dist/films.js`. Similarity is cosine similarity of mean-pooled, L2-normalized embeddings, clamped to [0, 1]. These scores are bundled in `dist/synopsis-scores.js`. For personal labels, the same quantized model and its runtime are bundled under `dist/models` and `dist/vendor`. On localhost the page calls `POST /api/label-embeddings`, which runs the bundled model on this computer and caches vectors. If that endpoint is unavailable (including on static hosting), a browser worker loads about 45 MB from this site and runs inference locally. Vectors are cached in browser storage. No API key, remote model download, or third-party inference service is used. Names are not sent to the label endpoint.

- **Title similarity:** MiniLM meaning embeddings of the exact film titles, mean-pooled and L2-normalized; clamped cosine similarity. This compares title meaning rather than literal spelling.
- **Poster appearance:** deterministic low-level features of the local poster files. Combines 65% similarity of square-root RGB color histograms with 35% similarity of spatial color means on a 4×4 grid. No learned semantic model is used for this source.
- **Poster meaning (CLIP):** actual quantized `Xenova/clip-vit-base-patch32` image projection embeddings, L2-normalized and compared by clamped cosine similarity. These compare poster imagery, including lettering, rather than movie content itself. DINO is not used.

`dist/media-scores.js` bundles all three new matrices plus exact film ordering, poster SHA-256 hashes and method provenance. Rebuild with Node 22+ using `node scripts/build-media-scores.mjs`. The build reads local posters, uses the bundled MiniLM model for titles, and downloads CLIP weights into the ignored `.cache/transformers` directory once. Inference runs locally; no images or participant data are uploaded. Visitors load only the small bundled score matrices, not CLIP weights. Each computational source has a cached UMAP projection from its chord distances. Projections are centered, normalized to the same RMS radius, and rotated/reflected to match a fixed synopsis reference. Influence sliders blend these aligned coordinates by relative weight, rather than rerunning UMAP on a new combined graph for every tick. A fixed frame prevents rescaling as weights change. Personal ratings then pull films toward magnets. Pairwise inspector affinities still summarize weighted source similarities; they are not exact map distances. The pair inspector shows each source’s score and method. All source weights persist per participant. Initial candidate groups still use synopsis similarity alone.

The personal layout combines labels into shared theme magnets. Singular/plural variants collapse; automatic semantic merges use complete linkage with cosine similarity above 0.6, so weak similarity chains cannot absorb a distinct theme. The explicitly requested “whimsical worlds” / “fantastical” equivalence is recorded in `dist/theme-preferences.js`. A representative original label names each theme, whose embedding averages its members. Click a theme to inspect every original label and its source relationships, separate a grouping, or combine it with another theme. Participant-specific grouping choices persist. A magnet-count slider moves from one broad theme to all automatically identified themes. Reducing the count repeatedly merges the closest theme centroids, recomputes theme embeddings and semantic positions, and rearranges the films around the resulting magnets. Increasing the count restores more specific themes. Every original label remains inspectable; count selection persists. Theme magnets use distinct pastel colors and no star icon. Each film is pulled once per shared theme even if several of its original labels map to that theme. A sparse graph links each theme to its strongest related neighbors using cosine similarity boosted by shared-film associations. Local attraction, gentle repulsion, and text-overlap correction allow compact clusters and empty canvas areas; there is no fit-to-canvas spreading step. Existing dragged positions still override these proposals; each film is pulled toward the centroid of its own theme magnets. Aligned per-source UMAP projections blend continuously; personal ratings then blend each film’s position toward its theme target. Poster overlap is corrected separately from semantic coordinates; dots and dotted leaders identify any displaced posters. The personal pairwise score in the inspector is a summary, not the force driving this layout. Similarity does not infer an opposition relation. Drag magnets (or use arrow keys) to revise their positions; each participant’s adjustments persist, and reset restores the semantic arrangement. Original pairwise statements remain inspectable regardless of their influence. Lines are hidden until a poster is hovered or keyboard-focused; only that film’s incident connections are revealed. Touch or keyboard activation can pin the reveal; Escape clears it. Dashed lines show the two strongest neighbors for each film above 0.4; the selector provides access to every pair. Reveal and click a connection to inspect the exact inputs and scores, then revise its label. The map workspace fits the viewport and does not scroll with the page. The left sidebar scrolls independently. Click-and-drag empty canvas to pan; two-finger trackpad scrolling also pans. Pinch to zoom on touchscreens and trackpads (including Safari GestureEvents); zoom stays anchored under the gesture. The plus/minus buttons remain available and the percentage button fits the map into view. Pair contributions also fit the viewport without page scrolling.

To recalculate synopsis embeddings after editing film summaries, install the optional build dependency with `npm install --no-save @huggingface/transformers@3.8.1`, then run `node scripts/build-synopsis.mjs`. This downloads the public `Xenova/all-MiniLM-L6-v2` model. Names are never model inputs. Personal labels are model inputs on this computer through the local server or browser worker. Failed loading exposes its cause in a details panel and offers retry. Missing personal scores are excluded until ready; it never silently falls back to the previous link-only method. The worker coalesces rapid edits to avoid building up an obsolete inference queue.

Film posters are stored in `dist/posters`, with source URLs in `dist/films.js`, referenced through the [Studio Ghibli API](https://ghibliapi.vercel.app/) from [TMDB](https://www.themoviedb.org/). Poster artwork belongs to its respective rights holders; this prototype is not endorsed by TMDB or Studio Ghibli. Poster appearance and CLIP comparisons are optional map influences.

Research question: **How does negotiating between personal associations and computational descriptions help people articulate their interpretations of media?**

Run `npm test` for label aggregation and profile-comparison checks. Model assets include their license information.

The older artwork collection and fetch scripts remain in the repository but are not loaded by this prototype.

## Movie layout and reproducible comparison

`dist/umap-layout.js` uses PAIR-code’s `umap-js` 1.4.0, bundled locally with its MIT license. Each source projection uses exact nearest neighbors from its own metadata, text or poster chord distances (`sqrt(2*(1-score))`), not distances between rows of the similarity matrix. UMAP runs for 400 epochs with a saved seed. Neighborhood size ranges from 2 to 9 for ten films, and packing (`minDist`) ranges from 0 to 0.99. Users can adjust both live, try another seed, or reset to 4 neighbors / 0.20 packing / seed 42. These settings persist per participant. Projection caching and animation-frame coalescing keep repeated magnet drags and slider changes responsive.

Poster spacing resolves only actual overlaps, without imposing the synopsis ordering on other sources. Films can change neighbors and swap sides when the selected evidence changes. Source and UMAP slider updates animate posters for 550 ms, starting from their current visible positions if interrupted. Connections hide during movement to avoid pointing at future positions. Reduced-motion preferences disable these transitions. Slider events coalesce per animation frame and preserve zoom/pan; initial map entry and the explicit fit button still fit the scene.

Personal magnets are applied after the UMAP blend: each film blends from its projected position toward its rating-weighted theme target, with pull `personalWeight * ratingStrength / (computationalWeight + personalWeight * ratingStrength)`. With personal influence only, labeled films reach their targets. With all sources off, films form a neutral circle. UMAP controls are disabled when all computational sources are off. Group-labeling suggestions remain average-link clusters of original synopsis similarity, independently of the map projection. UMAP gaps are not proof of distinct categories.

`dist/movie-layout.js` retains the previous MDS solver for historical benchmarks and provides shared distance conversion and poster collision helpers. The live map uses UMAP rather than MDS.

The map layout has no rectangular clamping. A uniform transform preserves aspect ratio; a separate poster collision pass changes only rendering. Fit view includes scene bounds rather than changing semantic coordinates. Theme placement retains its existing semantic clustering algorithm.

Run `node benchmarks/compare-layouts.cjs` and `node benchmarks/render-comparison.cjs` from the repo root. The old solver is preserved in `benchmarks/legacy-layout.cjs`, with its untouched original function alongside it. Results go to `reports/layout-comparison.json` and the locally served `/layout-comparison.html`. Comparison uses the same ten films and all 45 pair distances, three source settings, and three board sizes; it contains no participant labels. Normalized stress uses the best single scale fit, and Recall@2 counts true nearest neighbors retained out of 20 (metadata ties use stable index ordering). Semantic anchors and rendered poster centers are measured separately. The JSON additionally evaluates both layouts against the old target-distance transform. These are dataset-specific checks, not general validation of semantic judgments. `npm test` covers exact planar recovery, monotonic stress, determinism, personal constraints, relative weights, collisions, and existing app behavior.
